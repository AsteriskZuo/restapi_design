# REST API 设计规范 v2

## 版本说明

v2 版本在 v1 "大而全" 的基础上进行了扁平化设计，主要改进：

- **结构简化**: 从 5 个文件精简为核心的基础规则和高级规则
- **内容扁平化**: 减少层次嵌套，用更简练的方式表达规则核心内容
- **实用性优先**: 突出必须遵循的基础规则，将可选特性归类到高级规则

## 使用指南

### 基础规则 (basic_design.md)

包含 **14 个核心规则**，这些是设计 REST API 时必须遵循的基本原则，按重要程度排序：

1. **版本号规范** - API 版本控制 (最高优先级)
2. **HTTP 方法** - 标准方法使用 (最高优先级)
3. **无状态设计** - 服务器不保存状态 (最高优先级)
4. **认证方式** - JWT Bearer Token (最高优先级)
5. **响应格式** - 统一的 JSON 格式 (最高优先级)
6. **URL 设计** - 避免动词形式 (高优先级)
7. **数据传递** - 简单参数 vs 复杂数据 (高优先级)
8. **状态码** - 常用 HTTP 状态码 (高优先级)
9. **分页规范** - 分页参数和响应 (高优先级)
10. **缓存控制** - 基础缓存策略 (高优先级)
11. **频率限制** - API 调用频率控制 (高优先级)
12. **内容分类** - 按业务领域分类 (中优先级)
13. **命名规范** - URL 命名最佳实践 (中优先级)
14. **方法选择** - HTTP 方法使用指南 (中优先级)

### 高级规则 (advance_design.md)

包含 **10 个高级特性**，这些是可选的增强功能：

1. **字段选择** - 返回字段过滤
2. **数据压缩** - gzip 压缩支持
3. **URL 限制** - URL 长度和嵌套深度限制
4. **批量操作** - 批量增删改操作规范
5. **响应头规范** - 详细的响应头设置
6. **国际化支持** - 多语言错误消息
7. **详细状态码** - 完整的 HTTP 状态码
8. **异步操作** - 长时间任务处理
9. **搜索过滤** - 高级查询功能
10. **文件操作** - 文件上传下载规范

### 术语表 (glossary.md)

详细解释重要概念：

- **安全 (Safe)** - HTTP 方法安全性
- **幂等 (Idempotent)** - 操作幂等性
- **可缓存 (Cacheable)** - 响应缓存特性

### 产品定制 (im_design.md)

针对 IM 产品的具体设计，包括：

- 资源分类 (auth, users, groups, rooms, messages, push)
- URL 结构设计

### 问题记录 (issues.md)

记录现有产品中的实际问题：

- 命名不一致问题
- URL 结构不统一
- 动词形式 URL 使用

## 实施建议

### 第一阶段：最高优先级 (必须实施)

优先实施规则 1-5：版本号、HTTP 方法、无状态、认证、响应格式

### 第二阶段：高优先级 (强烈建议)

实施规则 6-11：URL 设计、数据传递、状态码、分页、缓存、频率限制

### 第三阶段：中优先级 (建议实施)

实施规则 12-14：内容分类、命名规范、方法选择

### 第四阶段：高级特性 (可选)

根据业务需求选择性实施 `advance_design.md` 中的高级特性

### 第五阶段：持续改进

- 定期 review 现有 API 设计
- 记录新发现的问题到 `issues.md`
- 根据实际使用情况调整规则

## 设计原则

v2 版本遵循以下设计原则：

1. **简洁性** - 规则简洁明了，易于理解和实施
2. **实用性** - 侧重实际开发中的常见场景
3. **扩展性** - 基础规则稳定，高级特性可灵活选择
4. **一致性** - 所有规则保持风格和术语统一
5. **可操作性** - 每个规则都有具体的示例和实施指导
